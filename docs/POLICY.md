# VillaMate 운영 정책

> 기능 구현 과정에서 결정된 비즈니스/운영 정책을 기록합니다.
> 코드에 반영된 결정과 보류된 결정을 모두 포함합니다.

---

## 1. 구독 정책

### 1-1. 무료 체험 (FREE_TRIAL)

| 항목 | 결정 | 근거 |
|------|------|------|
| 체험 기간 | 빌라 등록일로부터 **30일** | 빌라 생성 시 `subscriptionExpiry = 생성일 + 30일` 자동 설정 |
| 체험 횟수 | 계정 생애 **1회** | `User.hasUsedTrial` 플래그로 관리 |
| 이양 후 재사용 | **불가** | 플래그는 이양 후에도 유지됨 |
| 가격 | **19,900원/월** (`lib/pricing.ts`) | |

**구현 위치**: `app/api/villas/route.ts` (POST), `prisma/schema.prisma` (`User.hasUsedTrial`)

### 1-2. 중복 수령 방지 검토 기록

**Q. 같은 건물을 다른 사람이 새로 등록해서 무료 체험을 받을 수 있지 않나?**
→ 기술적으로 가능하나, 기존 빌라 데이터(입주민·청구서·장부)를 처음부터 재구성해야 하므로 현실적 동기가 없음. 허용 리스크로 판단.

**Q. 새 이메일로 새 계정을 만들면 무료 체험을 다시 받을 수 있지 않나?**
→ 마찬가지로 허용 리스크로 판단. 본인인증(SMS/PASS) 도입 시 해소되나 현 단계에서 보류.

### 1-3. 본인인증 도입 (보류)

| 방식 | 효과 | 보류 사유 |
|------|------|---------|
| SMS 인증 | 중간 (번호 변경 시 우회 가능) | 건당 비용 발생, 현 단계 남용 위험 낮음 |
| PASS 앱 인증 | 높음 (주민번호 연동) | 사업자 등록 + PASS 사업자 계약 필요 |

**재검토 조건**: 실제 무료 체험 남용 사례가 확인될 때. 도입 순서는 SMS → PASS.
PASS 인증은 전자투표 본인인증(F-61)과 함께 검토 예정.

## 2. 동대표 이양 정책

| 항목 | 동작 |
|------|------|
| 구독 상태·만료일 | 빌라에 귀속 → 새 동대표가 그대로 이어받음 |
| 기존 동대표 | `role = RESIDENT`로 변경 |
| 새 동대표 | `role = ADMIN`으로 변경 |
| 무료 체험 플래그 | 기존 동대표의 `hasUsedTrial` 유지 (이양 후 새 빌라 생성 시 무료 체험 불가) |
| 대상 | 해당 빌라의 `APPROVED` 입주민만 이양 가능 |

**구현 위치**: `app/api/villas/[villaId]/transfer-admin/route.ts`

---

## 3. 구독 만료 처리

| 상태 | 조건 | 처리 |
|------|------|------|
| FREE_TRIAL | `subscriptionExpiry < 현재` | 크론이 `EXPIRED`로 변경 + 관리자 알림 |
| ACTIVE | `subscriptionExpiry < 현재` | 크론이 `EXPIRED`로 변경 + 관리자 알림 |
| `subscriptionExpiry = null` | — | 크론이 처리하지 않음 (SUPER_ADMIN 수동 관리 대상) |

**구현 위치**: `app/api/cron/expire-subscriptions/route.ts`

> **주의**: 기존에 `subscriptionExpiry = null`인 FREE_TRIAL 빌라는 자동 만료되지 않습니다.
> SUPER_ADMIN이 백오피스에서 수동으로 만료일을 설정해야 합니다.

## 4. 기타 운영 결정

| 항목 | 결정 | 비고 |
|------|------|------|
| `fixedFee = null`인 빌라의 청구서 발행 | 0원 청구서 발행 허용 | 변동 청구 항목만 있는 빌라도 청구서 흐름 유지 |
| 청구서 자동 발행 | 매월 `autoPublishDay`일 크론 실행 | `app/api/cron/publish-invoices` |
| 전출 정산 정책 | 일할 계산 (F-95) | 월 고정비 ÷ 해당 월 일수 × 거주 일수 |
