## 1. 구독 정책

### 1-1. 무료 체험 (FREE_TRIAL)

| 항목 | 결정 | 근거 |
|------|------|------|
| 체험 기간 | 빌라 등록일로부터 **30일** | 빌라 생성 시 `subscriptionExpiry = 생성일 + 30일` 자동 설정 |
| 체험 횟수 | 계정 생애 **1회** | `User.hasUsedTrial` 플래그로 관리 |
| 이양 후 재사용 | **불가** | 플래그는 이양 후에도 유지됨 |
| 가격 | **19,900원/월** (`lib/pricing.ts`) | |

**구현 위치**: `app/api/villas/route.ts` (POST), `prisma/schema.prisma` (`User.hasUsedTrial`)

### 1-2. 중복 수령 방지 검토 기록

**Q. 같은 건물을 다른 사람이 새로 등록해서 무료 체험을 받을 수 있지 않나?**
→ 기술적으로 가능하나, 기존 빌라 데이터(입주민·청구서·장부)를 처음부터 재구성해야 하므로 현실적 동기가 없음. 허용 리스크로 판단.

**Q. 새 이메일로 새 계정을 만들면 무료 체험을 다시 받을 수 있지 않나?**
→ 마찬가지로 허용 리스크로 판단. 본인인증(SMS/PASS) 도입 시 해소되나 현 단계에서 보류.

### 1-3. 본인인증 도입 (보류)

| 방식 | 효과 | 보류 사유 |
|------|------|---------|
| SMS 인증 | 중간 (번호 변경 시 우회 가능) | 건당 비용 발생, 현 단계 남용 위험 낮음 |
| PASS 앱 인증 | 높음 (주민번호 연동) | 사업자 등록 + PASS 사업자 계약 필요 |

**재검토 조건**: 실제 무료 체험 남용 사례가 확인될 때. 도입 순서는 SMS → PASS.
PASS 인증은 전자투표 본인인증(F-61)과 함께 검토 예정.

### 1-4. 구독 상태 전이 규칙

```
빌라 생성 → FREE_TRIAL (30일)
               ↓ 만료 or 결제 실패
            EXPIRED
               ↓ 결제 성공 (Toss 자동결제)
            ACTIVE (만료일 +1개월)
               ↓ 만료
            EXPIRED
```

> **미정**: EXPIRED 상태에서 기능 접근을 어느 수준까지 제한할지. 현재는 `requireActiveSubscription()` 가드가 일부 API에만 적용되어 있음. 전체 기능 제한 여부는 추후 결정 필요.

### 1-5. 구독 만료 처리

| 상태 | 조건 | 처리 |
|------|------|------|
| FREE_TRIAL | `subscriptionExpiry < 현재` | 크론이 `EXPIRED`로 변경 + 관리자 알림 |
| ACTIVE | `subscriptionExpiry < 현재` | 크론이 `EXPIRED`로 변경 + 관리자 알림 |
| `subscriptionExpiry = null` | — | 크론이 처리하지 않음 (SUPER_ADMIN 수동 관리 대상) |

**구현 위치**: `app/api/cron/expire-subscriptions/route.ts` (매일 15:00 UTC 실행)

> **주의**: `subscriptionExpiry = null`인 FREE_TRIAL 빌라는 자동 만료되지 않습니다.
> SUPER_ADMIN이 백오피스에서 수동으로 만료일을 설정해야 합니다.

## 2. 결제 정책

> **미작성** — 아래 항목에 대한 정책 결정 및 문서화 필요.

- **자동결제 실패 시 처리**: 실패 시 즉시 EXPIRED 처리할지, 유예 기간(grace period)을 줄지. 현재 자동결제 크론(`cron/auto-payment`)은 실패 시 로그만 기록하고 상태를 바꾸지 않음.
- **유예 기간(Grace Period)**: 결제 실패 후 며칠간 기능을 유지할지. 현재 미구현.
- **재결제 시도 횟수**: 자동결제 실패 시 몇 번까지 재시도할지. 현재 1회만 시도.
- **환불 정책**: 중도 해지 시 일할 환불 여부. 현재 미구현 (Toss 수동 취소).
- **결제 수단 변경**: 빌링키 교체 시 기존 청구 주기 처리 방식.
- **쿠폰/할인**: `SubscriptionCoupon` 모델 존재. 쿠폰 중복 사용, 적용 순서 정책 미정.

## 3. 계정·권한 정책

> **미작성** — 아래 항목에 대한 정책 결정 및 문서화 필요.

- **역할(Role) 전환 규칙**: RESIDENT → ADMIN은 빌라 생성 시 자동 승격. ADMIN → RESIDENT는 이양 시에만 가능. SUPER_ADMIN은 DB 직접 설정만 가능.
- **멀티 빌라**: 한 동대표가 여러 빌라를 관리할 수 있음. 두 번째 빌라부터는 무료 체험 없음.
- **듀얼 모드**: ADMIN이 같은 빌라의 입주민이기도 한 경우, 관리자 뷰와 입주민 뷰를 전환 가능. 전환 기준: `User.residentVilla` 존재 여부.
- **계정 탈퇴**: 탈퇴 기능 미구현. 탈퇴 시 빌라·입주민·청구 데이터 처리 방침 미정.
- **비밀번호 분실**: 현재 비밀번호 재설정 기능 없음. 이메일 기반 재설정 또는 CS 직접 처리 필요.
- **소셜 로그인 계정의 비밀번호**: 소셜 로그인 계정은 `password = null`. 비밀번호 로그인 병행 가능 여부 미정.

## 4. 동대표 이양 정책

| 항목 | 동작 |
|------|------|
| 구독 상태·만료일 | 빌라에 귀속 → 새 동대표가 그대로 이어받음 |
| 기존 동대표 | `role = RESIDENT`로 변경 |
| 새 동대표 | `role = ADMIN`으로 변경 |
| 무료 체험 플래그 | 기존 동대표의 `hasUsedTrial` 유지 (이양 후 새 빌라 생성 시 무료 체험 불가) |
| 대상 | 해당 빌라의 `APPROVED` 입주민만 이양 가능 |

**구현 위치**: `app/api/villas/[villaId]/transfer-admin/route.ts`

> **미정**: 이양 대상자가 이미 다른 빌라의 ADMIN인 경우 처리 방식. 현재 역할이 덮어써져 기존 빌라 관리권을 잃을 수 있음.

## 5. 입주민 관리 정책

> **미작성** — 아래 항목에 대한 정책 결정 및 문서화 필요.

- **가입 승인 절차**: 입주민이 초대코드 입력 후 동대표 승인 필요. 자동 승인 옵션 없음.
- **거절 후 재신청**: 거절된 입주민이 재신청할 수 있는지, 횟수 제한이 있는지.
- **전출 처리**: 현재 `ResidentRecord` 하드 삭제. 납부 이력이 있으면 FK 제약으로 삭제 불가 → 409 반환. 소프트 삭제(`MOVED_OUT` 상태) 전환 필요 (기술 부채).
- **세대주 vs 구성원(MEMBER)**: 세대주가 전출하면 구성원은 어떻게 처리할지 미정.
- **같은 호수 중복 등록**: 현재 `(villaId, roomNumber, userId)` unique 제약만 있음. 동일 호수에 다른 세대주가 등록될 수 있음.
- **전출 정산(일할 계산)**: 월 고정비 ÷ 해당 월 일수 × 거주 일수. `app/api/residents/[id]/prorata` 참고.

## 6. 청구서·관리비 정책

> **일부 작성** — 추가 문서화 필요.

- **`fixedFee = null` 빌라**: 0원 청구서 발행 허용. 변동 청구 항목만 있는 빌라도 청구서 흐름을 유지하기 위함.
- **자동 발행**: 매월 `autoPublishDay`일에 크론이 `FIXED` 타입 청구서 자동 발행. `app/api/cron/publish-invoices`.
- **청구서 유형**: `FIXED`(고정 관리비), `VARIABLE`(변동 관리비). 두 타입이 같은 달에 공존 가능.
- **미납 처리**: 미납 시 알림 발송만. 자동 연체료·차단 정책 없음.
- **미납 리마인더 중복 방지**: 알림 body 문자열 패턴 매칭으로 당일 중복 발송 방지. 문구 변경 시 regex도 함께 수정 필요 (취약점, 기술 부채).
- **청구서 수정**: 발행 후 수정 가능 여부 미정. 현재 API 없음.
- **청구서 삭제**: 삭제 시 연결된 납부 이력 처리 방침 미정.

> **미정**: PortOne(KG Inicis) 결제 후 영수증 발급 방식, 세금계산서 발급 여부.

## 7. 알림 정책

> **미작성** — 아래 항목에 대한 정책 결정 및 문서화 필요.

- **알림 채널**: 앱 내 DB 알림 + Web Push 두 가지. 카카오 알림톡(F-32, F-37)은 사업자 등록 후 추가 예정.
- **Web Push 수신 거부**: 현재 opt-out 없음. 브라우저 레벨 차단만 가능.
- **야간 넛지 opt-out**: F-100 계획 시 `User.nightNudgeOptOut` 플래그 추가 예정.
- **크론 알림 중복 방지**: 각 크론이 당일 이미 발송된 알림을 DB에서 조회 후 중복 방지. 조회 기준: `type`, `title`, `createdAt >= 오늘 00:00 UTC`.
- **알림 보존 기간**: 읽은 알림을 언제까지 보관할지 미정. 현재 삭제 정책 없음.
- **구독 만료 사전 경고**: D-7, D-3, D-1 리마인더 발송. `app/api/cron/subscription-reminder`.

## 8. 데이터 보존·삭제 정책

> **미작성** — 서비스 성장 전 결정 필요한 중요 항목.

- **구독 만료 후 데이터 접근**: EXPIRED 상태 빌라의 데이터가 잠기는지, 읽기는 가능한지 미정. 현재 일부 API만 `requireActiveSubscription()` 가드 적용.
- **구독 만료 후 데이터 보존 기간**: 장기 미납 시 데이터를 언제까지 보관할지 미정.
- **계정 탈퇴 시 데이터**: 개인정보보호법상 탈퇴 후 즉시 삭제 or 일정 기간 보존 선택 필요. 현재 탈퇴 기능 미구현.
- **입주민 전출 후 납부 이력**: 현재 `InvoicePayment`는 `ResidentRecord`에 FK로 연결. 전출(삭제) 시 이력 보존 방식 미정 (소프트 삭제 전환 필요).
- **로그 보존**: API 오류 로그, 결제 로그 보존 기간 미정.

## 9. 커뮤니티·투표 정책

> **미작성** — 아래 항목에 대한 정책 결정 및 문서화 필요.

- **게시글 수정·삭제 권한**: 작성자 본인 + ADMIN. 삭제 시 댓글 처리 방식(cascade 삭제 여부).
- **게시글 신고·차단**: 신고 기능 없음. 이슈 발생 시 ADMIN이 직접 삭제.
- **투표 수정**: 투표 진행 중 선택지 변경 허용 여부. 현재 미정.
- **투표 마감**: 마감일 경과 시 자동 종료 여부. 현재 수동 종료만 가능.
- **투표 결과 공개 시점**: 마감 전에도 중간 결과를 공개할지 미정.
- **중복 투표 방지**: `Vote` 테이블 `(pollId, userId)` unique 제약으로 방지.
- **공동 당번(Duty) 순환**: 등록된 호수 순서대로 순환. 결번 호수·공석 처리 방침 미정.

## 10. 보안 정책

> **미작성** — 아래 항목 문서화 필요.

- **JWT 유효 기간**: 30일. 갱신(refresh token) 없음 — 만료 시 재로그인 필요.
- **비밀번호 정책**: 최소 길이·복잡도 요건 미설정. 현재 bcrypt(cost=10) 해싱만 적용.
- **Rate Limit**: 인메모리 Rate Limit 제거됨(기술 부채 참고). Vercel Edge 또는 DB 기반 재도입 검토 필요.
- **CSRF 방어**: Origin/Referer 헤더 검증. 미들웨어에서 변경 메서드(POST/PUT/PATCH/DELETE)에 적용.
- **XSS 방어**: Rich Text(가이드 본문)는 DOMPurify로 sanitize 후 저장·렌더링.
- **암호화**: Toss 빌링키는 AES-256-GCM 암호화 저장. `BILLING_ENCRYPTION_KEY` Vercel 환경변수 필수.
- **백오피스 세션**: `bo_session` HttpOnly 쿠키(8시간) + `bo_token` localStorage 이중 관리.

## 11. SUPER_ADMIN 운영 정책

> **미작성** — CS·운영팀 온보딩 시 필요한 내용.

- **계정 생성**: DB 직접 또는 `scripts/create-superadmin.ts` 실행. 현재 셀프 회원가입 불가.
- **빌라 구독 수동 변경**: 백오피스 → 빌라 목록 → 상태 변경. 만료일 없는 FREE_TRIAL 빌라는 수동 설정 필요.
- **쿠폰 발급**: `SubscriptionCoupon` 테이블 직접 INSERT 또는 API 예정. 현재 운영 UI 없음.
- **사용자 문의 대응**: 계정 삭제·비밀번호 초기화는 DB 직접 처리. CS 프로세스 미정.
- **데이터 조회 범위**: 백오피스에서 빌라·사용자·청구 현황 조회 가능. 개별 입주민 게시글·투표 내용은 조회 불가(미구현).
